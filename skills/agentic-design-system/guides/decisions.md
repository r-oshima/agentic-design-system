# 最初に決めること

依頼と資料から埋める。読み取れず、既定値では結果が大きく変わる項目だけをユーザーに聞く。

| 項目 | 内容 | 既定値 |
| --- | --- | --- |
| 対象 | プロダクト、使う人、主な作業、対象メディア（Web、デスクトップ、モバイル） | なし。必ず確かめる |
| テーマ | lightとdarkのどちらを持つか | 両方。片方だけの場合も、kernelは2つのテーマファイルを前提にするため、もう片方は同じ値にする |
| リファレンス | 参考にするサイトやアプリと、見るページ | なし。ない場合はDesign Principlesと一般的な基準から設計する |
| 再現の度合い | リファレンスがある場合だけ。リファレンスごとの`fidelity`。`inspire`（参考にするが、同じにはこだわらない）か`match`（できる限り同じ見た目にする）。値が正確に取れるか（指定値か推定値か）とは別に決める | `inspire` |
| 借りないもの | リファレンスがある場合だけ。ロゴ、イラスト、固有の文言、データなど | ロゴ、イラスト、固有の文言、ユーザーのデータ |
| リファレンスの操作 | リファレンスがある場合だけ。閲覧だけか、テーマの切り替えやデータの作成もしてよいか | 閲覧と、テーマを切り替えて元に戻すこと |
| 品質の基準 | コントラストの基準。リファレンスがある場合は、再現より優先するか | WCAG 2.2 AA（文字4.5:1、アイコンとfocusの外周3:1）。再現より優先する |
| 色の系列 | ニュートラルと強調色の系列。ブランドの色があればその値 | ニュートラル1系列と強調色1系列。ブランドの色もリファレンスもない場合は、強調色の色相をユーザーに聞く |
| 密度 | 情報をどれだけ詰めるか（一覧中心の業務ツールか、読み物か、タッチ中心か） | 対象メディアと主な作業から決める |
| 最初に作る画面 | Design Systemを使って最初に作る画面 | なし。ない場合はFoundationまでで止める |

## 聞き方

- 1回にまとめて聞く。項目ごとに既定値と、それを選んだ場合の結果を添える。
- 答えが曖昧で値や手順に落とせない場合（「いい感じで」「Linearっぽく」「高級感がある」など）は、既定値を含む2〜3個の具体的な選択肢を示して聞き直す。リファレンスなら見る画面と借りるもの（色、密度、部品の形など）、印象を表す言葉なら密度・色・角丸などの具体的な違いを選んでもらう。
- 答えどうしが食い違う場合（「密度は高め」と「タッチ中心」など）は、どちらを優先するか聞く。
- リファレンスがログインの必要なアプリの場合は、使える道具（ブラウザの操作など）と、操作してよい範囲を確かめる。
- 手順2に進む前に、全項目の結論を一覧にして見せ、この理解で進めてよいかを確かめる。既定値や仮定で埋めた項目には印を付け、「おまかせ」と答えた項目も既定値の中身を書く。
- 答えはADRに残す。リファレンスに関するものはreferencesにも残す。会話の中だけで終わらせない。
