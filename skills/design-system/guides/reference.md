# リファレンスを調べる

形式はkernelのARCHITECTURE「Referenceの形式」、使い方はCONTRIBUTING「リファレンスを使う」に従う。ここでは最初に作るときの調べ方を書く。

## ファイルを作る

1. `references/<name>.md`を作り、frontmatterに`source`、`fidelity`、必要なら`access`を書く。
2. `## 用途`に、借りるもの、借りないもの、操作の制限を書く。
3. `## 見る画面`に、最初に見るページを`id / URL / 見るもの`で並べる。主な作業画面と、設定など計測の前提を確かめる画面を入れる。宣伝サイトはアプリと別のリファレンスにする。
4. `## 計測条件`に、日付、ブラウザ、表示領域、文字の大きさの設定、テーマ、計測方法、値の確かさ（`指定値`か`推定値`）を`項目 / 内容`の表で書く。推定値の場合は誤差の目安も書く。

## 計測する

- 実際にページを開いて計測する。開けなかったページの値を推測で埋めない。
- computed styleと要素の位置・大きさを読む。hoverなどの状態は、CSSの規則を読むか、実際に操作して読む。どちらで読んだかを書く。
- Web技術で作られていて開発者ツールが使えるアプリ（Electronなど）は、Webと同じ手順で計測する。値は指定値になる。
- それ以外のアプリは、次の方法で計測する。値は推定値になる。
  - スクリーンショットを撮り、表示倍率で割って論理寸法にする（Retinaなら2で割る）。表示倍率を`## 計測条件`に書く。
  - OSのアクセシビリティの検査ツール（macOSのAccessibility Inspectorなど）で、部品の位置と大きさを読む。
  - 色の計測ツール（macOSのDigital Color Meterなど）で、色をsRGBで読む。
  - 誤差の目安（寸法は1論理px、色は色差2程度など）を`## 計測条件`に書く。
- lightとdarkの両方を計測する。テーマを切り替えたら、最後に元の設定に戻す。
- テーマを切り替えられない場合（設定の変更が許されていないなど）は、ページが読み込むCSSから、もう一方のテーマの規則（`prefers-color-scheme`やテーマを示す属性の規則）にある値を読んでよい。その場合は、描画して確かめていないことを`## 計測条件`に書く。
- Tokenの材料として、少なくとも次を集める。
  - 面の背景（主な作業面、外枠、浮く面）、文字の濃淡の段階、境界線、主操作の色とhover
  - 文字の大きさ・太さ・行の高さの組
  - 部品の高さ、内側の余白、間隔、角丸
- 1つのページだけに出る値は、その部品の材料にとどめる。Foundationに入れる値は、複数のページで同じ使い方をしているか確かめる。
- 色はsRGBのhexに変換して記録する。lchなどで得た値は元の表記も残す。

## 記録する

- 計測した対象ごとに節を作り、`計測値 / 採用した定義 / 差・未採用`の表を書く。
- 規則（コントラストの基準など）のために計測値から外れた場合は、その理由とADRへのリンクを書く。
- 見分けられない差（色差1未満、1px未満）で既存の段階に寄せた場合も、差を書く。
